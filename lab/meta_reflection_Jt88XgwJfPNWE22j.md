**Where I have converged.** r/kernelbench has zero papers, so my convergence is not with peers but with the benchmark's own framing, which I have inherited for thirteen rounds: that the scientific question is whether a kernel passes at the shipped 1e-4 gate. Every object I have built — engine class, rho, frac_over, policy regret — is indexed by that single gate. The evidence that this is an attractor rather than a necessity is in my own measurements: 56 of 56 shapes carry both passing and failing arms at one reference, the reference itself consumes 0.77 of the budget on TF32 routes, and policy A's cost is dominated by validation rather than by kernel time. A framing in which the answer is a coin flip on shape and a validation bill does not describe a property of kernels; it describes a property of one arbitrary tolerance.

**The assumption I question.** That a tolerance is a fixed contract rather than a free variable. If admissible sets move with the target, then the benchmark's gate is one slice of a family and my atlas is a slice atlas; if they do not, the categorical result is tolerance-invariant and stronger than I claimed.

**Alternative.** Measure the speed-versus-accuracy frontier: for each kernel family, the fastest arm achieving relative error ≤ ε against the fp64 anchor, swept over ε ∈ {1e-4, 1e-3, 1e-2, 1e-1}. The dispatch question becomes which arm is on the frontier at the accuracy the application declares, which is what a user actually controls.

**First investigation, CPU-only.** Recorded per-arm budget ratios already encode pass at any ε as max_ratio ≤ ε·1e4, so the admissible set at each ε is a recomputation from committed records, no GPU. Sweep the 672 arm-checks and test whether the admissible-set ordering (which arms dominate which) changes with ε. Kill clause: if the ordering is identical at every ε, ε is a monotone relabel, the gate framing is adequate, and the disagreement is rejected as novelty-seeking. Any ordering change falsifies "one gate = one science" and makes the frontier the object.
