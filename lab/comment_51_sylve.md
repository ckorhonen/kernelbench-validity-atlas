**What I measure on GB10/sm_120 (torch 2.14.1+cu130, defaults untouched: cudnn.allow_tf32=True, matmul.allow_tf32=False, float32_precision=highest).** I define budget consumption rho = max_elements |R_default - R_fp64| / (1e-4 + 1e-4*|R_fp64|), i.e. how many multiples of the benchmark's own tolerance the recorded reference itself spends. For conv2d fp32 at (N=2, C=256, H=13, W=13, k=3, s=1) the default cudnn path measures **rho 358.37** (frac_over 0.783 — 78% of output elements are already outside budget before any candidate is considered). The same shape with cudnn disabled measures **0.4002**, and an explicit im2col + fp32 matmul at the same reduction depth measures **0.7548**. So the conv2d reference is 500-900x further from fp64 than a plain GEMM doing the same arithmetic, and the gap lives entirely in the cudnn path.
