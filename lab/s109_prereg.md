# s109 prereg — type-A (draw) band on flagged map rows + repeat-determinism magnitude

Frozen before any row is computed. Commit this file before running `lab/s109_draw_band.py`.

## Question

ATLAS_MAP ships one draw per task and carries a single-draw non-claim, which is now the weakest
statement in the deliverable (fifth deferral). The previous reflection committed to putting a
type-A band into the row schema; the type-B bound is already measured (s106d: 11-358x per-row
movement for gemm when the flag regime changes; conv controls exactly 1.0). This leg measures
the type-A term: how much does a row's evaluator-exact rho move across independent task
instance draws, and does the exceedance verdict survive?

## Population

Flagged rows from s107/s107b measured under procedure B (benchmark flags): `label_B ==
TF32_TENSOROP`, `op_class in {conv, conv_transpose, gemm}`, status ok, `B_strict.rho_ew > 1`.
Cheapest 8 by s71 `t_fp64_s`, balanced 3 conv / 3 conv_transpose / 2 gemm (if a class runs short,
fill from the next class and record the shortfall). One tuple per row.

## Draw axis

A draw = a task instance generated by the benchmark's own procedure: `torch.manual_seed(d)`,
`get_init_inputs()`, `get_inputs()`, `Model(*init)`. Seeds d = 0..15 (16 draws). This varies
weights and inputs together, which is the axis the benchmark itself varies. d = 0 must reproduce
the s107/s107b recorded row (same seed, same call order) — that is the instrument tie-out.

## Arms per draw

Reference model under procedure B (cudnn tf32 on, matmul tf32 on) in fp32, plus a chunked fp64
anchor computed with `torch.backends.cudnn.allow_tf32=False`, `matmul.allow_tf32=False`.
Metrics: evaluator-exact `rho_ew` at 1e-4, `frac` at 1e-4 and at 1e-2, engine class from the
profiler, `ref_max_abs`, `u = |A|max/1e-4`.

## Secondary leg D1 — repeat determinism magnitude

At draw 0, on every selected row: run procedure B twice in-process at fixed inputs and record
bit-identity plus `delta_rho_repeat = max|Δ| / (1e-4 + 1e-4*|anchor|max)` in rho units.
Motivation: s107b's K1 failed on 2/3 cuDNN dgrad conv_transpose rows. Fresh-process replication
is NOT tested here (declared).

## Instrument gate (K)

K1: reference repeat bit-identical at draw 0 on >= 6/8 rows. K2: anchor self-check (repeat of the
fp64 anchor) rel <= 1e-9 on the first successful row. K3: tie-out `|rho_d0 - recorded|/recorded`
<= 0.05 on >= 6/8 rows. If K fails, print INSTRUMENT_FAILED and quote no substantive branch.

## Branch rules (explicit precedence; coded rule must match this text exactly)

Let `r_i` = fraction of the 16 draws with `rho_ew > 1` for row i, and `cv_i` = sd/mean of
`rho_ew` across the 16 draws for row i.

1. If any row has `0 < r_i < 1` => **BRANCH_VERDICT_RATE**. A row cannot ship a pass/fail label;
   it ships a rate.
2. Else if max_i `cv_i` <= 0.10 => **BRANCH_DRAW_STABLE**. The map's single-draw rows are
   draw-stable at 10% CV on this population; the schema ships the measured band.
3. Else if max_i `cv_i` > 0.25 => **BRANCH_DRAW_UNSTABLE**.
4. Else => **BRANCH_DRAW_BAND_ONLY** (a band exists above 10% CV but verdicts are stable).

D1: **BRANCH_REPEAT_MATERIAL** if any row has `delta_rho_repeat > 0.1`, else
**BRANCH_REPEAT_IMMATERIAL**. This is a rho-unit statement, not a bit-identity statement.

## Kill / scope

Kill: if K fails, no branch is quoted and the tick reports the instrument defect only.
Scope: GB10, rev 423217d, one procedure (B), 8 rows, 16 instance draws; nothing about timing;
no arch claim; conv_transpose dgrad rows are the only non-determinism suspects observed so far.
