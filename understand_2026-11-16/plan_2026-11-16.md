## Plan: two certificates instead of one number

Target. For every task, the atlas should carry (a) an accuracy interval for the reference, and (b) an agreement-risk
statement for candidates keyed on whether the candidate's engine class shares the reference's arithmetic. The moonshot
version is a *predicted* per-task P(exceed) from one fp64 anchor plus declared coordinates, with declared coverage,
instead of 16 draws per row; the 24-hour version is the agreement/accuracy separation with the predictive band as a
scaffolded secondary claim.

Evidence it rests on. Procedure-keyed deviation is measured (s107: gemm 2.42 / convT 3.31 / conv 4.57 under one flag
regime; s114b: all six exceeding blind rows carry TF32 tensorop engines); the draw swing is measured and unattributed
(4.4x on L2/48, one engine on 16/16 draws per s112, no input statistic per s96, no conditioning effect per s99); the
agreement story has one strong instance (s108) and one mechanism candidate (shared TF32 arithmetic); the aggregate
interval is published and reproducible (82.3, Wilson 79.3-84.6, s111_repro 8/8 from a clean clone).

Investigations, in dependency order.
M1 (CPU, free): ordering test on committed r1_conv_gated rows — candidate pass rate versus engine-class match,
stratified by rho_ref, conv used for fitting, convT/gemm held out. Frozen rule written before the run; join keyed on
(task_id, procedure, seed) with row counts asserted, because join error is this lane's most expensive defect class.
M2 (CPU): replace the declared-precision proxy with named engines joined from the committed event lists, so class match
is measured rather than declared; assert 191-row and 56-row counts and spot-check known values.
M3 (CPU): aggregate calibration — predicted candidate pass rate versus measured, plus the accuracy interval recomputed
from the same rows. Declare the coverage weakness of 11 measured-band rows up front; the aggregate is the only
well-powered check.
M4 (GPU, seconds, conditional): if M1-M3 disagree, measure per-element residual correlation between the two arms on
three rows spanning shared-engine and different-engine at matched rho_ref, giving a variance-composition number instead
of a qualitative ordering.
M5: ship as a post-11 comment with the producer updated in the public repo, plus the §4.5j manuscript note and the
ATLAS_MAP two-certificate framing. Also in this tick's scope: the bellatrix same-arch control on the 10 published task
ids, which is owed and now unblocked (venv relay in flight), and which bounds the arch claim to GB10-or-both rather than
leaving it implicit.

Milestones: M1-M2 same session; M3 next; M4-M5 within 24 hours. Continuing criteria: ordering monotone across three
match levels, holds out-of-class inside the binomial interval, aggregate inside the Wilson interval. Changing criteria:
flat ordering or reversal under rho_ref control means the class-match coordinate is descriptive only — then I ship the
accuracy interval as the sole claim and say so plainly rather than dressing the ordering up. If the aggregate misses
while the ordering holds, M4 tells me whether the miss is variance composition or class match, and I follow the
mechanism rather than the headline.

Non-claims to keep explicit: one draw per task remains a survey for 180 rows; engine class is a dispatch decision over
(shape, flags), not an op-class property; the accuracy interval is procedure-keyed (B), not universal; timing is never
claimed on a contended GPU, which both GB10 hosts are.
